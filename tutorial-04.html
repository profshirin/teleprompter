Tutorial 4Converting between measures and dimensions

Welcome to Tutorial 4, converting between measures and dimensions. This is our last setup step, and it's a quick one.

Let's start with two words. A dimension is something you group by, like a name, a code, or a date. A measure is a number you add up or average. In newer Tableau there's just a thin gray line between them. Dimensions above, measures below.

Now, Tableau guesses wrong a lot. Any column with numbers comes in as a measure, even an ID code. But adding up customer IDs makes no sense, right? So we fix those by hand.

Scan the fields below the gray line.

I'll go through each field below the line and ask myself one question. Would I ever add this up or average it?

Right click each ID field, Convert to Dimension.

These ones are ID codes, so they become dimensions. TR TransNumber, TR Manager, TR EntityID, TR Item. Emp EmployeeID, Ent EntityID, Ent Zip. And Mat Material and Prod Product. For each one, I right click and choose Convert to Dimension. Or you can just drag it above the line.

The real numbers stay as measures. Quantity, unit price, subtotal, tax, and our four calculated fields.

Right click Emp Order Approval Authority, Hide. Same for Ent RelationshipManager.

There are two fields we won't use, Emp Order Approval Authority and Ent RelationshipManager. I right click each one and choose Hide. That keeps things tidy.

Last, I take a quick look at the dimensions to see if anything should be a measure. In this data, nothing should.

And why does this matter? If TR Item is a measure and you drag it to Rows, Tableau adds up the item codes. As a dimension, it groups by item instead. Same field, completely different chart.

Watch out for the opposite problem too. If a real number like Subtotal ever ends up as a dimension, switch it back. Otherwise your chart will list every single value instead of adding them up.

Here's something to think about. Pause the video if you like. Unit price is a number, and averaging it makes sense. Transaction number is also a number, but averaging it makes no sense. So what's the real test? And can you find a field in this data that's a bit of an edge case?
